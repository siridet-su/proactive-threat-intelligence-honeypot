# Web-login-only scope and service posture

## Objective

Keep the web-corp decoy focused on HTTP login collection, stop unused web-stack
containers, and verify that the active request path no longer records ordinary
page or scan requests.

## Procedure

- Built `decoy-honeypot-web-corp` from the tracked
  `integrations/web-corp/` Docker context and recreated only the `web-corp`
  HTTP service with `--no-deps`.
- Ran the in-process web-corp suite inside the built image.
- Issued a read-only `GET /web/login` against `http://10.58.33.42`.
- Inspected container states, command arguments, and host listening sockets.
- Stopped only web-corp HTTPS, Odoo, FTP, and SMTP. Did not delete containers,
  volumes, or collected event data.

## Expected result

- Login POSTs alone create web-login spool records; all login attempts are
  rejected, and SQLi-shaped input receives heuristic indicator labels.
- Page GETs, bait/scan paths, unrelated POSTs, and 404s create no application
  telemetry and no Uvicorn access log.
- HTTP remains on the ZeroTier-bound host port 80. Container port 8080 is not
  a host listener; Pi HTTPS 443, FTP, SMTP, and Odoo are stopped.
- Cowrie, Zeek, telemetry agents, PostgreSQL, and Deception Core remain active.

## Observed result

- All 7 web-corp tests passed inside the built image. They verify that GETs,
  bait paths, 404s, and unrelated POSTs create no spool files, while a login
  POST creates one; the SQLi-shaped login remains rejected and tagged.
- Live `GET /web/login` returned HTTP 200. The deployed container command
  includes Uvicorn `--no-access-log`.
- `ss -ltnp` showed web-corp on `10.58.33.42:80` only; no host listener on
  `:8080` or `:443`. Container inspection showed HTTP active and Pi HTTPS,
  Odoo, FTP, and SMTP exited. FTP/SMTP have exit code 137 with
  `OOMKilled=false`; their stop exceeded the graceful timeout. Odoo/HTTPS exited
  with code 0.
- `go test ./...` passed in both `agents/collector-agent` and
  `agents/processor-agent`; `git diff --check` passed.
- PostgreSQL `127.0.0.1:5432` and Deception Core `127.0.0.1:9000` remained
  active for Cowrie integrations. Cowrie, Zeek, collector, processor, TI,
  hardware, and response-agent systemd units reported active.

## Limitations

- No live login POST was made, avoiding a new credential-bearing record in
  Redis/MongoDB. End-to-end persistence is covered by the prior
  [2026-09-24 pipeline validation](2026-09-24-web-login-pipeline.md), not by
  this deployment check.
- The host Python environment does not have FastAPI; tests ran in the app image.
- The external Compose file is outside this repository and still defines the
  stopped services. A full-stack `docker compose up` could reactivate them.
- Collector/processor support for the prior `web_http_request` shape remains
  during queue drain; any prior page/scan records are historical, not newly
  generated by the current app.
- No public VPS HTTPS, dashboard query/view, FTP/SMTP adapter, or protocol test
  was implemented here.

## Follow-up

Keep FTP/SMTP stopped until their credential/log policy, normalized adapter,
and dashboard/API path are designed. Migrate or separately scope cleanup of the
external Compose definitions. Implement the dashboard path for existing
web-login MongoDB events and treat public VPS HTTPS as a separate deployment.
