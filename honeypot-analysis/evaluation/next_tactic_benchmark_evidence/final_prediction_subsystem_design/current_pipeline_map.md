## Active runtime path

1. `production/workers/session_worker.py` applies each Cowrie event to `SessionMonitor`. Prediction snapshots are gated by `prediction_triggers` in `configs/prediction_policy.trusted.json`: login success/failure, file upload/download, session close, and every `cowrie.command.*` event.
2. `SessionWorker._save_prediction_snapshot_unobserved` builds a redacted session payload, applies deterministic session correlations and campaign context, calls `production/prediction/session_features.py:build_session_features`, and then calls `RealtimePredictionEngine.predict`.
3. Runtime feature extraction retains substantially more information than the historical training payload: ordered trusted classifications, techniques, source counts, confidence summaries, command count, command timing, login state, session age/duration, sensor, enrichment, and deterministic behavior flags. The active VOMM authority actually consumes only the tactic/technique transition fields relevant to its scorer.
4. `SessionWorker._load_external_transition_model` uses `production/prediction/external_vomm_artifact.py:load_external_vomm_artifact` to bind artifact, manifest, expected model ID, manifest ID, and artifact SHA-256. Missing or mismatched artifacts fail closed.
5. `RealtimePredictionEngine._predict_external_hard_backoff` is the active authoritative branch. It queries `external_seed_transition`, uses longest supported prefix then technique/tactic backoff according to the existing scorer contract, and emits `predicted`, `abstained`, or `model_unavailable`. Local transition output is stored only in `local_shadow_prediction`; heuristic progression is score-free `generic_progression_prior`.
6. `SessionWorker` optionally builds `smb_decision.v1`, evaluates predictive-alert policy, and writes the whole snapshot through `storage.save_prediction_snapshot`. SQLite stores the immutable JSON payload in `prediction_snapshots`; MongoDB has contract parity but is not implied to be active by this review.
7. `production/workers/analysis_worker.py` loads the latest snapshot and passes it into the reporting pipeline. `threat_hypothesis.py:attach_model_prediction` creates a separate `model_prediction` block, and `session_assessment.py:forecast_section` keeps it separate from observed claims.
8. `production/reporting/response_guidance.py` validates guidance against canonical observed-behavior references. Prediction-only, asset-only, malformed, copied, or forged evidence cannot make an action eligible. Historical report contracts remain additive and are not silently rewritten.
9. `production/api/dashboard_api.py`, `production/api/monitor_web.py`, and `production/api/static/monitor.html` expose the status, ranking, artifact identity, local shadow diagnostic, and non-empirical prior. Older snapshots without v2 status remain readable through compatibility inference.

## Active authority and lifecycle facts

- Active policy: `prediction_mode=external_hard_backoff_vomm`, source order exactly `["external_seed_transition"]`, no fallback scorer, no weighted ensemble.
- External artifact SHA-256: `b5a60951764648ed242d7b9acfe1df6f5f314f96e341badb7f4bd55107614e3e`.
- External manifest SHA-256: `01c0665566467693e3dbb408f0383900f7d09e769d27c93161937b27d7d6d429`.
- Selected Transformer checkpoint SHA-256: `d9b316d76e63b15b175668aa0bf69cfe4172bbd812d6b19743a628cd0ec8073d`; it is offline only and not imported by the worker.
- `honeypot-prediction-backtest.timer` runs weekly; prediction retention is audited daily. The calibration worker can write weight proposals, but example configuration has `apply_output=false`, and weights cannot influence the external-authority branch.
- Predictive alerts are configured with `block_external_seed_only=true`; the sole active authority is external-only, so prediction-only alerts are suppressed. This is configuration-enforced rather than a simpler architectural impossibility.

## Current information loss and ambiguity

- Raw-event and command grouping are lost before public training.
- Labels attached to one command are flattened into an artificial order.
- Adjacent repetition count and phase duration are lost.
- Sessions with no transition and terminal prefixes are absent from the task.
- Historical preprocessing cannot reproduce runtime confidence, timing, login, or transfer features.
- Timestamp-free evidence cannot independently prove chronology.
- Validation seed selection and calibration diagnostics reuse the same evidenced half.
- “Confidence” labels in runtime VOMM snapshots are policy labels over raw scores, not calibrated probabilities.
- Current Transformer softmax values are raw scores, not calibrated probabilities.
