# Model2 T1046/T1110 live audit — 2026-09-24

This is a record of controlled tests against the project's own public Cowrie
endpoint and four existing Model2 decoy ports. It is not a claim of model
accuracy or of validated ATT&CK findings.

## T1110: observed failures, Model2 positive

- Canonical session: `session_v1_37d6e920ad42f498109fe3bab26481e3`.
- Cowrie recorded two `cowrie.login.failed` events in the same session.
- Model2 spool: `VALID_SHADOW / AVAILABLE` with run, measurement, episode,
  artifact, PCAP, and Zeek binding.
- Session-detail API: T1110 `PRESENT / MODEL2_ONLY`; T1105 `ABSENT`;
  T1046 `NOT_OBSERVED`.
- No classification, canonical finding, hypothesis set, or response action was
  created for this authentication-only session. This separation is correct:
  Model2 is a non-authoritative shadow signal.
- Public source-IP TI endpoint returned `TI_AVAILABLE`; AI advisory endpoint
  returned `not_available`; Next Distinct returned `SESSION_ENDED`; PDF endpoint
  returned 404 because no report was stored for this short session.

One successful-login control session also produced `VALID_SHADOW`; its T1110
prediction was `ABSENT`.
This test demonstrates a positive output on one small controlled example,
not sensitivity/specificity or generalization.

## T1046: four exact flows, but no exact session identity

- Canonical session: `session_v1_ada027dc2079cfc32a51ccff1e3c957f`.
- While Cowrie was active, the test client made exactly one TCP connection to
  each existing owned decoy port 80, 443, 445, and 3306.
- Sensor receipts exist for all four; Model2 spool is `VALID_SHADOW / AVAILABLE`
  with `sensor_flow_count=4`, run/measurement/episode IDs, and PCAP/Zeek PASS.
- Those sensor receipts contain source IP, ports, and timestamps, but no
  `session_id`, `run_id`, `measurement_id`, or `episode_id`.
- The spool has no `t1046_observation`; session-detail consequently reports
  T1046 `NOT_OBSERVED / t1046_multiservice_scan_evidence_missing`. This is an
  appropriate fail-closed result; source-IP/time coincidence is not proof of
  exact-session identity.
- The model separately predicted T1105 and T1110 `PRESENT / MODEL2_ONLY`
  despite no observed download or repeated failed login in this scan session.
  These are shadow false-positive candidates, not trusted findings.
- Session-detail reported two trusted observations from Cowrie commands,
  zero hypothesis sets and zero response actions. TI was available from three
  stored source-IP cache records. AI advisory was accepted. Next Distinct
  returned a historical forecast. The dynamic PDF endpoint returned 200 and
  explicitly displayed T1046 as an unavailable Model2 head.

## Local hardening and remaining requirement

The T1046 applicability gate was hardened locally to require all four
identities on both the marker and the result, with exact equality. A regression
test demonstrates that a claimed exact-binding marker with only ports and flow
UIDs remains unavailable. This ensemble gate patch has **not** been deployed.

The GCP Model2 receiver was updated separately with a receipt selector that
excludes unbound sensor flows from the model's feature vector and emits a
session-bound T1046 marker only for exact receipt/PCAP/Zeek matches. The Pi
sensor was not modified. The deployment kept a backup and rollback path at
`/var/backups/model2-transfer-20260924-r4`. Local targeted tests passed
32/32 before deployment.

After deployment, a fresh short Cowrie session
`session_v1_d174981a35ea61887178e6fe196caba6` (sensor session
`aea4b1388d2f`) generated a `VALID_SHADOW` result with PCAP/Zeek PASS. The
test client also connected to the four owned decoy ports while it was active.
The unbound receipts were correctly excluded (`sensor_flow_count=0`), and the
result marker said `observed=false / NO_EXACT_MULTISERVICE_BINDING` with all
four run/session/measurement/episode identities recorded. Session-detail HTTP
200 projected T1046 unavailable (`t1046_not_observed`) and T1105/T1110
`ABSENT`. This verifies fail-closed behavior, **not** successful T1046
corroboration. A prior overlong test session returned
`MODEL2_UNAVAILABLE / episode_window_invalid` because its measured window
exceeded the 60-second contract; the short control avoided that condition.

To make T1046 applicable without misattribution, an authenticated sensor producer must
generate an independently verifiable session/measurement-bound scan receipt
at observation time (or an equivalent cryptographically bound challenge).
It must then link exact PCAP/Zeek flow UIDs and at least two destination ports
to that receipt. Neither adding IDs to old receipts after the fact nor setting
the marker from source IP and time alone satisfies the contract. The current
model artifact, architecture, policies, and historical data were not changed.
